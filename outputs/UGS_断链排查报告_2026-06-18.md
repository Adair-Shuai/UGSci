## 一、导航注册缺失（3 项）

  ```ts
  { id: 'ugs-capabilities', labelKey: 'tab.ugsCapabilities', routeId: 'ugs-capabilities' },
  { id: 'ugs-skills', labelKey: 'tab.ugsSkills', routeId: 'ugs-skills' },
  { id: 'ugs-experts', labelKey: 'tab.ugsExperts', routeId: 'ugs-experts' },
  ```

### 🟡 问题 2：CMDK 命令面板未收录 UGS 路由

- **位置：** `packages/app-config/src/routes/index.ts:166-169`

- **影响：** Ctrl+K 命令面板的 Navigate 分组中搜索不到 UGS 三页，无法快捷键跳转

### 🟡 问题 3：BusinessDesktopRoutes 未注册 UGS 路由

- **位置：** `src/spa/router/BusinessDesktopRoutes.tsx` — 整文件为空数组占位
- **影响：** 若后续商业版/桌面版有独立路由注入逻辑，UGS 路由将被遗漏
- **状态：** 当前无实际影响（路由已通过 `sharedMainAreaChildren` 注入），但应标记为风险点

## 三、UGS 功能模块断点（4 项）

### 🔴 问题 7：presetMcps.ts 硬编码用户特定路径

- **位置：** `src/features/UgsCapabilities/presetMcps.ts:17-18,45-48`
- **描述：** NeqSim 和 pyResToolbox 的 `command` 和 `args` 中包含当前用户(`shuai`)的绝对路径
  ```ts
  command: 'C:\\Users\\shuai\\.workbuddy\\binaries\\java\\versions\\21\\bin\\java.exe',
  command: 'C:\\Users\\shuai\\Documents\\pyrestoolbox\\.venv\\Scripts\\fastmcp.exe',
  ```
- **影响：** 任何非 `shuai` 用户或不同环境的部署会直接失败
- **修复：** 改为环境变量或相对路径

### 🔴 问题 8：AddSkillButton 安装后不刷新连接器列表

- **位置：** `src/features/UgsCapabilities/index.tsx:263-269`
- **描述：** `onPostInstall` 回调仅 `message.success('能力已添加')`，未调用 `fetchConnectors()`
- **影响：** 用户在能力市场安装 MCP 后，能力中心列表不自动更新；需手动刷新页面
- **注意：** 虽有一个监听 `installedPluginsCount` 的 `useEffect`（行 171-173），但 `CustomConnectorModal` 安装的自定义 MCP 不走 `installMCPPlugin` 路径，不会触发该计数器变化
- **修复：** 在 `onPostInstall` 回调中调用 `fetchConnectors()`

### 🟡 问题 9：AddSkillButton 安装后不刷新已安装技能

- **位置：** `src/features/UgsSkills/index.tsx:108`
- **描述：** `<AddSkillButton />` 未传 `onPostInstall` 回调
- **影响：** 通过添加按钮安装技能后，「已安装」Tab 角标和列表不自动更新
- **修复：** 传入 `onPostInstall` 回调触发 store 刷新

### 🟡 问题 10：getConnectorCategory 与 getCategoryByIdentifier 数据重复

- **位置：** `src/features/UgsCapabilities/index.tsx:139-151` vs `capabilityData.ts:106-108`
- **描述：** 同一定义在两处维护，映射表不一致（index.tsx 少 3 个条目）
- **影响：** 维护时可能不同步
- **修复：** 统一定义到 `capabilityData.ts` 的 `MCP_CATEGORY_MAP`，index.tsx 仅引用

## 四、Store 初始化竞态（2 项）

### 🟡 问题 11：useInitPresetMcps 与 useFetchInstalledPlugins 竞态

- **位置：** `src/features/UgsCapabilities/useInitPresetMcps.ts:14-39` + `index.tsx:157,159`
- **描述：** 两 hook 在同一组件中同时调用。首次渲染时 `installedPlugins` 为空 `[]`，所有预置 MCP 被标记为缺失并触发异步安装。后续 `useFetchInstalledPlugins` 完成后数据才真正就绪
- **影响：** 每次页面加载都发起不必要的 MCP 安装请求（服务器应跳过重复安装，但请求开销存在）
- **修复：** 在 `useEffect` 中增加 `loadingInstallPlugins` 检查，确保插件列表加载完成后才执行安装

### 🟡 问题 12：useFetchInstalledPlugins 不在全局启动流程中

- **位置：** 未在 `StoreInitialization` 或全局 provider 中调用
- **影响：** 访问 `installedPlugins` 的组件在首次渲染时看到空列表，直到用户导航到某个调用此 hook 的页面
- **注意：** 这是 LobeHub 上游的设计模式，UGS 未改变此行为
- **状态：** 设计行为，但 UGS 三页都依赖此数据，考虑在 SPAGlobalProvider 层预取

## 五、Service/API 断链（4 项）

### 🟡 问题 13：reportSkillEvent 前端调用但无后端实现

- **位置：** `src/services/discover.ts:567-579`（前端定义），调用点：`community/(list)/skill/features/List/Item.tsx`、`community/(detail)/user/features/UserSkillCard.tsx`
- **描述：** 前端正常调用 `discoverService.reportSkillEvent({ event, identifier, source })`，但函数体 `void payload` — 无实际后端端点
- **功能描述：** 报告的技能"点击"和"查看"事件，用于市场数据分析和推荐算法
- **复用建议：** 后端需要新增 `market.reportSkillEvent` tRPC 端点 → 调用 Market API `/api/v1/skills/events` 上报；当前所有技能交互事件静默丢失
- **状态：** 保留代码，待后端端点实现后即可复用
- **影响：** 技能事件统计功能完全不可用
- **修复：** 要么添加后端端点，要么注册为已知 TODO 而非 no-op

### 🟡 问题 14：getMcpManifest 前端包装未使用

- **位置：** `src/services/discover.ts:183-189`
- **描述：** `getMcpManifest` 包装方法无调用者。实际 MCP manifest 获取走 `getMCPPluginManifest`（discover.ts:191）直接调用 `lambdaClient.market.getMcpManifest`
- **功能描述：** 提供一个不传 `{ install }` 选项的简化 manifest 获取接口
- **复用建议：** 当前无场景需要排除 install 选项的 manifest 获取，可保留供未来纯查询场景使用

### 🟡 问题 15：chatGroupService 三个方法无消费者

- **位置：** `src/services/chatGroup/index.ts`
- **方法及功能：**
  - `batchCreateAgentsInGroup`(L114): 批量向团队添加多个 agent，接收 `{ groupId, agentConfigs }[]` → 返回 `{ groupId, agentIds }`
  - `transferGroup`(L155): 转移团队所有权，接收 `{ groupId, targetUserId }`
  - `getGroupAgents`(L140): 单独查询团队成员列表（当前 agents 数据通过 `getGroupDetail` 一并返回，但前端 selector `getGroupAgents` 从 store state 派生）
- **调用者分析：** 三方法前后端均完整定义，tRPC 路由也已注册（`apps/server/src/routers/lambda/agentGroup.ts:86/235/308`），但无前端组件/Store 调用
- **复用建议：**
  - `batchCreateAgentsInGroup` → 专家团建设中可复用：专家团召唤流程当前仅创建 supervisor agent，后续如需为每个成员 agent 批量注册到团队可调用此方法
  - `transferGroup` → 团队管理功能预留，当前未实现转移 UI
  - `getGroupAgents` → GroupTasks/Supervisor 组件通过 `getGroupDetail` 间接获取，独立查询接口暂不需要

### 🟡 问题 16：debugService 无消费者

- **位置：** `src/services/debug.ts`
- **描述：** 调试工具集合，定义但无任何前端组件 import
- **功能：** 可能包含开发环境下的状态检查、日志导出等调试能力
- **复用建议：** 可在开发环境中通过浏览器 console 暴露调试入口（如 `window.__ugsDebug = debugService`）
